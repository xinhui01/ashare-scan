## 修复东财资金流（真实会话 Cookie 方案）
- akshare `stock_individual_fund_flow` 只带老版 UA、无 Referer/真实 Cookie，易被东财服务端 reset。
  项目 `headers.random_eastmoney_cookie()` 是**伪造** Cookie，可能不被东财接受。
- 新建 `src/sources/eastmoney/fund_flow.py`：
  - `fetch_individual_fund_flow(stock, market)`：真实会话 Cookie 预取（先 GET quote.eastmoney.com 让服务端发 Set-Cookie）+ 完整浏览器头(`random_eastmoney_headers` 但移除手动 Cookie 头避免遮蔽真实 Cookie) + 多 host 兜底(push2his→push2→push2delay) + 全部直连(trust_env=False)。
  - 解析严格对齐 akshare 中文列（15 字段→13 字段），下游 `get_fund_flow_data` 列映射无需改动；已单测验证对齐。
  - `_em_fund_flow_reachable(timeout)`：启动探针复用同一套逻辑，避免裸请求误判东财"死"。
- `stock_data.py`：东财分支先试 `fetch_individual_fund_flow`，失败再 fallback akshare；`_probe_eastmoney_fund_flow` 改用 `_em_fund_flow_reachable`。
- 编译通过 + 解析单测通过（沙箱东财连不通，无法验证真实网络下是否绕过风控，需用户本机验证）。
- `_diag_em.py` 加一行"新逻辑(真实cookie+多host)"权威可达性判定，用户本机跑可确认修复是否有效。
- 局限：若是本机网络层 TCP 限制（ISP/防火墙），加真实 cookie 也无效，只能同花顺兜底。
