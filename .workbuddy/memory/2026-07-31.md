## 资金流抓取全失败排查（仅诊断，未改代码）
- 现象：个股资金流(002185/600036/000988)全部 ProxyError，`RemoteDisconnected`；历史K线正常(714行缓存新鲜)。
- 根因：`_set_proxy.bat` 仅做 TCP `Connect 127.0.0.1:7897` 判断 Clash 存活。7897 端口 TCP 开着（Clash 核心在跑），但**未真正提供 HTTP 代理服务**（可能 TUN-only / 监听端口不对 / 代理监听被关），于是 bat 设了 `HTTPS_PROXY=http://127.0.0.1:7897`，所有走 env 代理的网络请求都失败。
- 为何历史正常：历史K线走本地 sqlite 缓存(`data/stock_store.sqlite3`)，不触网；资金流必须联网(akshare→eastmoney、ths补位→d.10jqka.com.cn)，两条路径都读 env 代理→全挂。
- 实测：7897 TCP OPEN；经 7897 代理请求 → ProxyError(RemoteDisconnected)。沙箱内直连也报错是沙箱无外网，不代表本机。
- 临时解法（无需改码）：关掉/修好 Clash 的7897 HTTP代理，或退出 Clash 让 bat 清掉 HTTPS_PROXY 走直连。
- 根本修复方向（待用户确认）：① `_set_proxy.bat` 改为真正验证代理可用性(发真实 CONNECT/GET)再设变量；② 资金流网络路径显式 `trust_env=False`/`proxies=None` 绕过 env 代理（与 eastmoney history session 一致）。
- 启动链：`update_and_predict.bat`/`update_cache.bat`/`predict_today.bat`/`start_app.bat`/`sentiment.bat` 均 `call _set_proxy.bat`；bypass 开关 `ASHARE_SCAN_BYPASS_PROXY` 或 `USE_BYPASS_PROXY` 文件，本次未启用。
