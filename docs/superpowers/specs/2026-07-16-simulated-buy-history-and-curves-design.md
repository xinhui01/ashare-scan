# 模拟买入历史与收益曲线设计

## 目标

扩展“模拟买入”页，使其不再只展示当前预测日的候选，而是形成稳定、可追溯的模拟交易流水，并提供两类曲线：

1. 全部模拟交易按交易日等权、连续复利形成的账户累计收益曲线。
2. 选中某条历史记录后，从当日开盘买入到收盘卖出的个股分时收益曲线。

历史范围覆盖数据库中已有的全部预测记录。首次使用时自动补建历史流水，以后每次预测完成后自动追加当天记录。

## 已确认的交易口径

- 每个预测日自动选择最多两只不同股票，沿用现有模拟买入选股与去重规则。
- 实际交易日是预测日后的下一个有效交易日。
- 买入价取实际交易日开盘价。
- 卖出价取同一交易日收盘价。
- 单笔只持有一个交易日，不延续为持仓。
- 当日有两只可买股票时各占 50%；只有一只可评估且可买时，该股票代表当日全部有效组合收益。
- 一字板、停牌、价格缺失以及尚未回填的记录不参与账户收益计算，但必须保留在历史列表中并显示状态。
- 不考虑手续费、印花税、滑点及资金容量约束。

## 架构与职责

### 存储层

在 SQLite 中新增模拟交易流水表。每条记录至少包含：

- 预测日期和实际交易日期；
- 股票代码、名称、行业、题材；
- 来源类别、类别显示名、预测分、买点状态和入选依据；
- 买入价、卖出价和单笔收益率；
- 是否可买、交易状态及不可交易原因；
- 创建时间和更新时间。

表设置 `(prediction_date, code)` 唯一约束。现有选股服务已经对同一预测日的股票代码去重，因此该约束能够表达“一天同一只股票只形成一笔模拟交易”，也保证历史补建可安全重复执行。

存储接口负责：

- 批量插入或忽略已经存在的历史快照；
- 写入新预测产生的模拟交易快照；
- 从 T+1 评估结果回填交易日期、买卖价格、收益率和状态；
- 按日期读取全部历史流水。

### 模拟交易服务

扩展现有 `simulated_buy_service`，集中负责：

- 从保存的预测结果重建每天最多两只历史候选；
- 将候选转换为不可变的流水快照；
- 对等待中的流水应用 T+1 评估结果；
- 按交易日聚合有效单笔收益；
- 计算账户净值与累计收益曲线；
- 为 GUI 提供历史列表和统计摘要所需的纯数据结构。

历史补建时，过去没有保存过“当时最终入选结果”，因此使用当前已经存在的历史模拟买入重建规则生成最多两只候选，并在首次写入流水后固定。新预测则保存当次界面实际选中的两只股票。未来选股排序规则发生变化时，不重新覆盖已有流水。

### 分时曲线数据

个股图按需加载，不在页面启动时批量请求历史分时。选中流水记录后，以该记录的实际交易日期调用现有分时查询链：

1. 优先使用本地 `intraday_cache`；
2. 缓存没有时，允许现有数据源按目标交易日查询；
3. 将每个分时价格换算为相对买入价的收益率：`(price / buy_price - 1) * 100`；
4. 返回时间序列、0% 成本线、开盘买入点和收盘卖出点。

如果历史分时无法取得，图表区域显示“暂无该交易日分时数据”，历史流水和账户曲线仍正常可用。

### GUI 层

“模拟买入”页分为三块：

1. 顶部统计与账户累计收益曲线；
2. 全部历史模拟交易列表；
3. 当前选中记录的当日分时收益曲线。

GUI 只消费服务层生成的数据，不自行重算交易或账户收益。分时加载在后台执行，并使用请求标识校验返回结果；用户快速切换股票时，过期结果不得覆盖当前选择。

## 数据流程

### 首次历史补建

1. 列出全部已保存预测日期，并按日期读取预测结果。
2. 对每个预测日按历史重建规则生成最多两只候选。
3. 将候选批量写入流水，依靠唯一约束跳过已存在记录。
4. 读取该预测日已有的 T+1 逐股评估结果并回填流水。
5. 某个预测日损坏或无法读取时，记录日志并继续处理其他日期。

补建是幂等操作。页面以后再次打开时可以执行轻量同步，只处理缺失或仍等待回填的记录。

### 新预测与结果回填

1. 预测完成并选出模拟买入候选后，立即写入快照，初始状态为“等待交易”。
2. T+1 评估生成或刷新后，用 `(prediction_date, code, category)` 匹配评估结果并回填流水。
3. 若价格齐全且可买，状态变为“已完成”，保存开盘价、收盘价和开盘到收盘收益率。
4. 若一字板、停牌或缺少交易价格，状态变为相应的不可交易状态，不进入账户曲线。

流水的唯一身份不包含类别，因为每日候选已按代码去重；类别用于准确匹配评估结果和展示。

## 收益计算

单笔收益率为：

`trade_return = (sell_price / buy_price) - 1`

对同一实际交易日，取全部状态为“已完成”且可买的记录：

`daily_return = mean(trade_return_1, ..., trade_return_n)`

账户初始净值为 `1.0`，按实际交易日期升序连续复利：

`equity_t = equity_(t-1) * (1 + daily_return_t)`

曲线显示的累计收益率为：

`cumulative_return_pct = (equity_t - 1) * 100`

某日没有有效交易时，该日不产生新的曲线点，也不改变净值。统计摘要中的“累计收益”统一采用上述复利累计口径；“单笔平均收益”仍按所有有效单笔收益的算术平均值计算。

## 界面细节

### 顶部摘要和账户曲线

摘要显示总记录数、已完成数、有效交易数、胜率、账户累计收益和单笔平均收益。胜率沿用现有类别命中口径，不用“收益大于零”替代现有命中定义。

账户曲线：

- 横轴为实际交易日期；
- 纵轴为累计收益率百分比；
- 画出 0% 基准线；
- 数据不足时显示明确占位信息。

### 历史列表

默认按预测日期倒序排列，至少包含：

- 预测日、交易日；
- 代码、名称、来源；
- 买入价、卖出价；
- 单笔盈亏；
- 状态、入选依据。

等待 T+1 的记录显示“等待交易”；一字板、停牌和缺价记录显示对应原因，而不是统一显示成亏损或未命中。

### 个股分时曲线

- 横轴覆盖 09:30 至 15:00 的有效分时点；
- 纵轴为相对开盘买入价的涨跌幅；
- 开盘点标记“买入”，收盘点标记“卖出”；
- 显示 0% 成本基准线；
- 只展示买卖当天，不延伸到后续交易日；
- 未选中记录、等待交易或分时缺失时显示对应占位提示。

## 错误与降级处理

- 单个历史预测载荷损坏：跳过该日期并记日志，不中止整体补建。
- T+1 尚未到达：保留等待状态，后续同步再次尝试。
- 一字板或停牌：保留流水并排除在账户收益之外。
- 开盘价或收盘价缺失：不猜测价格，不计算收益。
- 历史分时缺失或网络请求失败：仅降级个股图。
- 页面销毁或选择变化后返回的异步数据：丢弃，不更新组件。
- 数据库重复补建：由唯一约束和幂等写入处理。

## 测试策略

### 存储测试

- 新表初始化与字段迁移；
- 流水插入、查询、回填；
- `(prediction_date, code)` 唯一约束；
- 重复补建不产生重复记录。

### 服务测试

- 现有全部预测日期能够补建历史候选；
- 新预测保存实际入选快照；
- T+1 价格和状态正确回填；
- 两只股票等权、一只有效、全部无效三种日收益场景；
- 多日按时间顺序复利；
- 待回填、一字板、停牌和缺价记录被正确排除；
- 分时价格正确换算为相对开盘收益率。

### GUI 测试

- 模拟买入页包含摘要、历史表、账户曲线和个股曲线；
- 列表按日期倒序展示并正确格式化状态和价格；
- 选择历史记录触发对应交易日的异步分时加载；
- 过期异步返回不会覆盖新选择；
- 无账户数据和无分时数据时显示降级提示。

## 验收标准

- 打开模拟买入页后，现有预测历史能够自动补成稳定的逐股流水。
- 重启应用或重复打开页面不会改变或重复已有历史记录。
- 新预测产生的最多两只模拟买入会固定追加到流水。
- T+1 完成后，列表显示实际开盘买入价、收盘卖出价和单笔收益。
- 账户曲线严格按每日有效股票等权、跨日复利计算。
- 点击已完成的历史记录后显示该交易日开盘至收盘的分时收益曲线。
- 一字板、停牌、待回填或分时缺失不会造成页面异常，并有明确状态提示。

## 非目标

- 不实现手动买入、手动卖出或持仓管理。
- 不支持跨日持有策略。
- 不引入手续费、滑点、仓位上限或现金流模拟。
- 不批量抓取所有历史分时数据。
- 不因未来选股算法变化而重写既有模拟交易流水。
