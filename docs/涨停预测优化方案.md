# 涨停预测优化方案（提交 Codex 审阅）

> 背景：用户反馈涨停预测成功率低，怀疑是「读取 25 天 vs 5 天数据」的窗口问题。
> 经实证分析，窗口几乎不影响结果；真正拉低命中率的是「候选名单无截断 + 类别不分优劣」。
> 本文给出可落地的代码改动 + 待跟进项，全部已写入 git，供 Codex 审阅。

---

## 一、核心结论（实证，非猜测）

### 1. 窗口长度（5天 vs 25天）对预测结果几乎无影响 —— 用户的原始假设不成立

证据（`data/verify_lookback.txt`，20 个实测交易日 07-07~08-03）：

| 检查项 | 结果 |
|--------|------|
| `latest_continuation_rate` 两组完全相同 | 20/20 = 100% |
| `avg_continuation_rate` 平均绝对差 | 1.41 个百分点 |
| `avg` 被实际读取的情况 | 仅当 `latest is None`，而 latest 100% 非空（`cont.py:309`） |
| 二波路径 `score_followthrough_candidate` 对 `lookback_days` 的敏感度 | 函数体写死 `lookback_days=90`，形参从未被使用 |

**含义**：5 天和 25 天吐出的候选名单基本是同一批，命中率不会有实质差异。硬回放 5-vs-25 跑出来也是同结果，不值得花 5 小时。

### 2. 真正提升命中率的两个杠杆（反事实，见 `data/counterfactual_out.txt`，3 窗口一致）

基线（全部候选，现状）：命中率 **14~16%**，平均收益为负。

**杠杆 A — 截断候选数**（解决热门日名单爆炸 50~100+ 只）：

| 策略 | 命中率(近20d) | 均收益 |
|------|------|------|
| 全部候选 | 14.38% | -0.22% |
| top-5（按分数） | 21.21% | +0.79% |
| top-3（按分数） | 26.67% | +1.28% |

**杠杆 B — 按类别筛**（比截断更猛）：

| 策略 | 命中率(近20d) | 均收益 |
|------|------|------|
| 只买 反包(wrap) | 32.61% | +1.84% |
| 反包+二波(first) | 24.22% | +1.19% |
| 反包+二波+保留(cont) 且 top-5 | **40.21%** | +2.08% |

**各类别单独命中率（近20d）**：反包 32.6% > 二波 18.3% ≈ 保留 19.7% > 趋势 8.7% > 首板 8.5%

**最优组合**：反包 + 二波 + 保留，且 top-5 → 命中率 ~30~40%，从 14% 干到 40%。

### 3. 评分标定错位（独立 bug，需跟进）

诊断 F：`predicted_score` 的**类别均值排序**与**实际命中率排序严重倒挂**：

| 类别 | 平均分 | 实际命中 | 标定判断 |
|------|------|------|------|
| 趋势涨停 | 98.1 | 8.7% | 分数第1 / 命中第5 → **高估 3 位** |
| 反包 | 84.8 | 32.6% | 分数第2 / 命中第1 → **低估 1 位** |
| 二波接力 | 68.3 | 18.3% | 一致 |
| 保留涨停 | 65.1 | 19.7% | 分数第4 / 命中第2 → 低估 2 位 |
| 首板涨停 | 53.7 | 8.5% | 一致 |

**实操含义**：不要用「分数高低」跨类别挑票（趋势分最高但最坑），要用**类别标签**筛（反包/二波优先）。这也是质量门用「类别优先级作主排序、分数作次排序」的原因。

## 二、已落地的代码改动

### 改动 1：候选质量门（核心优化）

**新增** `src/services/scoring/quality_gate.py`
- `apply_prediction_quality_gate(result, preset, ...)`：对预测结果 5 个类别子列表做「类别筛选 + top-N 截断」。
- 预设：`off`（默认，无副作用）/ `wrap_only` / `wrap_first` / `wrap_first_cont`。
- 通过环境变量 `LIMITUP_QUALITY_GATE` 切换，**不改代码即可启用**。
- 排序：主序=类别优先级（wrap>first>cont>fresh>trend），次序=分数降序（缓解跨类别分数错位）。
- 截断后按原类别放回各自子列表，**GUI / 竞价确认 字段结构不变**。
- 行为记入 `data_quality["quality_gate"]`，UI 可直接展示「本次质量门裁剪了多少」。

**修改** `src/services/scoring/predict.py`（结果组装处，约 2414 行后、落盘前）
```python
try:
    from src.services.scoring.quality_gate import apply_prediction_quality_gate
    result = apply_prediction_quality_gate(result, data_quality=data_quality, log_fn=log_fn)
except Exception as exc:
    logger.debug("候选质量门执行失败（已跳过，保留原结果）: %s", exc)
```
- 默认 `preset="off"` → 现有行为**完全不变**，零回归风险。

**启用方式**（审阅后由用户决定）：在运行环境设置 `LIMITUP_QUALITY_GATE=wrap_first_cont` 即可让盘前预测只输出反包+二波+保留的 top-5。

### 改动 2：修复 `score_followthrough_candidate` 死参数

**修改** `src/services/scoring/first.py`
- 形参 `lookback_days: int = 5` → `= 90`（与旧有效行为一致；所有调用方都显式传值，改默认安全）。
- 第 590 行 `_count_historical_followthrough(..., lookback_days=90, ...)` → `lookback_days=lookback_days`，**激活此前被写死的参数**。
- 影响有界：仅改变二波候选的历史形态加分窗口；主续板评分路径（latest_continuation_rate）与窗口无关，已实证。

## 三、待 Codex 跟进（非本次提交范围，建议后续 PR）

1. **评分标定修正（诊断F）**
   - 现状：`predicted_score` 跨类别均值排序与实际命中率倒挂（趋势高估、反包低估）。
   - 建议：在 `prediction_accuracy_service` 或评分模块加一层**按类别的分数校准**（如每个类别内做分位归一 / 用历史命中率反推权重），使「分数高 ≈ 命中高」在类别间也成立。
   - 校准后，质量门可进一步升级为「全局按校准分排序」而非「类别优先 + 分数次排序」。

2. **质量门增强**
   - 支持「每类别独立 top-N」预设（当前是合并后全局 top-N）。
   - 支持 `score_min` 阈值，剔除极低分候选。
   - 把质量门裁剪结果也写进 `snapshots/latest_prediction.json`（目前仅写 `data_quality`）。

3. **窗口参数的清理**
   - 既然实证证明 lookback 对结果无实质影响，可考虑在 UI/文档中移除「5天/25天」的误导性暗示，或统一为单一窗口，减少用户困惑。
